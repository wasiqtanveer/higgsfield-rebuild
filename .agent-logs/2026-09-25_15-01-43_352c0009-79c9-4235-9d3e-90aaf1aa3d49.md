All three pushbacks are fair. Taking them in turn, because two of them you're right about and one is a misunderstanding worth clearing up.

## 1. "Supabase has no API" — you're right to worry, and that instinct is the whole point

That was exactly my concern too. Supabase does auto-generate a REST API, but if your React app calls `supabase.from('generations').select()` directly, **you didn't write a backend** — you wired a client to a database. A reviewer looking for "a working database and API" sees a BaaS passthrough.

The fix isn't avoiding Supabase, it's **never letting the browser touch it**. Supabase becomes just Postgres + file storage, reached only from your own server code with the service-role key. Your API is yours: validation, auth, credit transactions, rate limiting, error shapes. That satisfies them *and* keeps Supabase's convenience — and since Supabase Storage holds the generated images too, it drops R2 and we're down to two services.

**So: Supabase stays. It sits behind your API, never in front of it.**

## 2. "We already have React, why Next now" — one clarification, then you win

Next.js *is* React — it's React plus a server and a router, not a different UI library. So it wouldn't have been a rewrite of your components.

But your actual point — why migrate build tooling with 36 hours left — is correct. **Keep Vite + React.** Vercel runs serverless functions from an `/api` folder right alongside a Vite app, so you get real server-side API handlers without touching your build setup. You write every route by hand, which is *better* signal than framework magic anyway.

## The product: forkable prompts

Concretely, so we build the same thing:

Every image is the child of a **prompt**, and prompts form a tree. Open any public image → you see its prompt, the chain it descends from, and a **Remix** button that loads that prompt into your composer to edit. Your version becomes a child, and the diff against its parent is visible. The feed shows lineage, not orphaned tiles.

Higgsfield has nothing like this — it shows you finished output and hides the prompt. That's your product argument: **the prompt is the artifact, not the image.**

Schema (this is where the "real backend" lives):
- `users`, `sessions`, `models`
- `prompts` — with `parent_prompt_id` self-reference, `root_id`, `depth`
- `generations` — status, image path, seed, provider, timings, errors
- `credit_ledger` — **an append-only ledger, not a counter.** Every generation writes a ledger row in the same transaction. Balance is derived. Refuses you when short.
- `likes`, `styles`

**Cut, and stated plainly in the README:** video generation (no free provider can do it honestly), audio, canvas, MCP, face swap, the 19-item nav rail, the 37-feature cloud, the 14 marketing bands, and the pricing page — replaced by one credits screen.
